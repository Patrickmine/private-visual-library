# 面向用户的对话示例

以下例子只指导表达，数量、文件名、分类及位置必须替换为本次真实结果。彩色符号和加粗直接以 Markdown 渲染，不把对话回复套进代码块；只有用户需要复制的调用提示或命令才用代码块。

## 提示样式

- 🔵 **请提供……**：需要输入，例如图片文件夹位置。
- 🟠 **请确认／选择／处理……**：需要用户决定，或补充有问题的文件信息。
- 🟢 **图库已经做好**：完成结果。

只加粗行动提示、需要关注的原文件名及关键结果。普通进度不整段加粗，不给每句话加符号。默认不展示 Gate 结论或引用 Skill 条款解释为何需要确认。

## 问“如何使用”

把图片文件夹的位置发给我即可。我会看图整理，先让你确认品类，再生成并打开图库。

生成的图库放在另一个文件夹里，包含图片副本，你的原图不会改变。以后打不开，可以告诉我“重新打开这份图库”。

🔵 **请提供图片文件夹的位置。**

用户需要可复制的调用方式时，只给短提示：

```text
使用 $private-visual-library，把这个文件夹的图片整理成私人图库：
【图片文件夹位置】
```

## 确定保存位置与处理范围

先解释新文件夹保存生成的图库，用户无需搬动原图。按本次风险、数量、用户要求和已确认约定选择样本或整批，不机械限定每次先做六张。需要确认时，把范围和位置放在同一条简短消息里；已授权的内容不重复询问。

示例：

这个文件夹有 19 张图片。按你先小范围试用的要求，我建议先做 6 张，新图库另存到桌面的“私人图库_试用”。

🟠 **请确认这次处理 6 张，并保存到这个位置。**

## 确认品类与无法判断的文件

展示简短的品类数量表，不堆叠四个维度的英文值。“未指定品类”有图片时，在同一条消息中集中列出完整原文件名及简短原因。不能只用“2、425、427”或网站内部 ID；有子目录或重名时用相对路径。文件名保留原空格和扩展名，必要时附原图。

示例：

图片已经整理好，品类如下：

【本批品类和数量表】

🟠 **这 3 张图片暂时无法确定品类：**

| 原文件名 | 原因 |
|---|---|
| **2.jpg** | 厨房全景，无法确定主要商品 |
| **图片 425.png** | 只展示面料局部 |
| **图片 427.png** | 只展示缝边局部 |

你可以告诉我它们属于什么商品，也可以保留为“未指定品类”。

🟠 **请确认品类清单，或指出需要调整的文件。**

没有未知品类时不展示空的补充请求，直接请用户确认清单。

## 用户修正后

用户只说“425 为被子”时，只修改指向明确的对应文件并保存原话，不代替整批确认。编号对应多个文件时先问清楚，不能任选一张。

示例：

**图片 425.png** 已改为被子，更新后被子共 2 张。这一归属会保留下来。

🟠 **如果整份清单没有其他调整，回复“确认”，我就继续生成。**

用户已经明确确认整份清单时，直接继续生成，不再询问是否可以开始，也不引用规则重复解释。

## 完成与下一步

日常生成只做主说明中的必要检查，以下例子不能套用未检查过的结果。默认交付打开链接、保存位置和短说明，内部保留必要的生成与恢复记录；详细报告、截图和压缩包仅按用户需要提供。

示例：

🟢 **你的图库已经做好，可以打开了。**

【打开图库的可点击链接】

本批 19 张图片已整理，页面显示和四个筛选维度已检查。新图库保存在【已确认的位置】，原图保持不变。

浏览时需要保持这次启动的服务运行；以后打不开，可以让我重新打开这份图库。本批已经完成，以后增加图片时可以生成新版，保留现在这一版。

不能宣称单图、翻页和返回已经测试，除非实际进行了相关测试。若仅确认资源可读取，不能说每张图片都已在浏览器实际显示；图片延迟加载不等于损坏。

样本交付的最后一句改为“请看一下是否符合你的预期；符合后可以继续整理剩余图片。”已有用户反馈后主动说明下一步，扩大范围仍需实际授权。

## 有问题时

直接说明实际影响与需要的信息，不用“Gate 不通过”或“资源请求失败”代替解释。无法读取的图片也列完整原文件名；不要要求用户重做已通过的技术检查。

示例：

🟠 **这 2 个文件目前无法读取：**

- **示例文件甲.png**
- **示例文件乙.jpg**

其他图片已经清点好。请提供这两个文件的可用版本，或确认本次先不处理它们。

无法完成某项浏览器检查时，如实说明未验证的部分，不把工具操作失败直接当成图库故障。仅在内置浏览器验证时，必要时注明“已在内置浏览器检查”，不冒充 Chrome 人工检查。用户主动询问技术诊断或明确要求正式报告时，再按需要提供细节。
